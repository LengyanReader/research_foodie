Self-model, gap awareness & bounded exploration · 自我模型·缺口意识·有界探索

What an agent can reliably know about itself, how to find its own gaps, and how to explore without fooling itself.

自己能知道什么、如何找到自己的缺口、以及怎样不自我欺骗地探索。

0. The asymmetry this doc is built on

A harness that claims a strength has produced testimony, not evidence. A harness that runs a task it has never run has produced evidence, not a claim. Everything below follows from that asymmetry: self-report is cheap and systematically optimistic; an external check is expensive and decisive. The purpose of a self-model is therefore not to assert capability but to index it — each entry points at the artefact that would disprove it.

This doc grounds M5.11 and the capability gap-seeking. It deliberately does not restate M5.1–M5.10 (the signal → audit → mutation → journal loop, and the round contract); those already exist. What is missing is the thing the loop assumes: a way to know what is not covered.

1. Classic foundations (named, not re-read)

Metacognition research separates monitoring ("do I know this?") from control ("what do I do about it") — the same split a harness needs between a self-model and a decision rule. The canonical sources (Flavell 1979; Nelson & Narens 1990) are not entered in review/references.md because no first-party record was reachable this session; they are named here so the lineage is honest, and no rule below rests on them. The empirically load-bearing part is §2, which is verified.

Two classic findings do transfer, and they are the reason this is a gate rather than a vibe:

  • Calibration and discrimination are different skills. A system can be accurate on average and useless as a guide to

its own reliability.

  • Confidence is a report, not a measurement. Asking for it changes nothing unless it is scored against outcomes.

3. Finding the gap

There are two kinds of gap, and they need different machinery.

guards, and clauses referenced but never anchored. That surface is mechanical and reliable within its own definition. It is also bounded by what the registry can express: it cannot see a direction nobody registered. So the register needs a second half — the roadmap entries that record deliberate non-additions with a reason and a revisit trigger (M5.10).

  1. Disconfirming check. Pick a claimed strength and try to falsify it, on purpose, once per round. Not "test the

feature" — try to make it fail. A strength that has never been attacked is an assumption.

  1. Error-taxonomy mining. Cluster real failures by mechanism, not by surface symptom. Two bugs with the same cause are

one gap; ten symptoms with ten causes are ten.

  1. Holdout pressure. Every new capability is measured on tasks it was not built from (M5.3). If the holdout never

surprises you, it is not a holdout — it is a regression test.

"more tests", "more sources" are all counts that can rise while quality falls. The guard is the one M5 already uses: a capability is claimed only when it changes an outcome on a task the harness did not choose to make itself look good on.

4. Exploring without self-deception

Open-ended search has a long, honest literature, and its central lesson is uncomfortable: novelty is not value.

MechanismSourceWhat it actually gives you
Quality-diversity (MAP-Elites)R208 (arXiv:1504.04909)Keeps a diverse set of good solutions instead of one optimum — the right shape for exploring "directions" rather than "answers".
POETR209 (arXiv:1901.01753)Co-evolves tasks and solutions; new tasks are generated because they are learnable-but-not-solved.
OMNIR210 (arXiv:2306.01711)Uses a model of "interestingness" to steer search — and makes the model of interestingness an explicit, attackable object.

definition-of-done (M5.10) like any other: a clause, a discriminator the engine can evaluate, a guard, provenance, a router row, reachability. Exploration changes what is on the list; it does not change what counts as done.

system acquires scope it cannot verify — the failure mode M5 already names as misevolution.

5. The self-improvement frontier, read sceptically

WorkSourceHonest reading
AI ScientistR212 (arXiv:2408.06292)An automated research loop (idea → experiment → write-up), evaluated with a model-based reviewer. Impressive as a loop; its quality claims inherit the reviewer's weaknesses.
Darwin Gödel MachineR213 (arXiv:2505.22954)Self-modifying agents kept in an archive and selected empirically — i.e. self-improvement implemented as search plus evaluation, not as introspection.
STOPR214 (arXiv:2310.02304)Recursive self-improvement of code, with the search space bounded by a scaffold; the gains are search gains.
Self-taught evaluatorsR215 (arXiv:2408.02666)Judgement can be bootstrapped without human labels — but bootstrapped judges inherit the generator's blind spots.
AlphaEvolveR218A first-party announcement (not peer-reviewed) of evolutionary search over code with automated evaluators. Treat as a strong demo, not as evidence about general self-improvement.

truth lives. A harness that wants to improve should invest in evaluation and provenance, not in introspection — which is exactly where M3 (gates) and M4 (integrity) already point.

6. What a harness should actually do

  1. Keep a self-model artefact (self-standard.md already is one). Each claimed strength names its evidence: a guard

test, a shipped file, a measured run. No evidence, no claim.

  1. Keep the gap register in two halves — the cycle audit surface (mechanical) and roadmap entries with reasons and

revisit triggers (deliberate). The first is a bug list; the second is a decision log.

  1. Run one disconfirming check per round. Choose a claimed strength; try to break it. Record the result either way.
  2. Route disagreement, don't average it. When self-assessment and an external check disagree, the external check wins;

the disagreement itself is a calibration data point (R207).

  1. Bound exploration — budget, holdout, stop condition — and let candidates enter only through the round gate.
  2. Never let a self-report sign off. Self-attributed strength is a hypothesis (R201, R205).

7. Deliberate non-additions & honest limits

  • No "consciousness"/"self-awareness" claim. This is engineering: an index of coverage plus a falsification habit. The

word "self-aware" is avoided deliberately.

  • No new introspection mechanism. The reliable path is external checks; adding a "reflect deeply" step would be the very

failure R201 documents.

  • No unbounded autonomy. Exploration is budgeted and human-gated (M0.8); the doc does not authorise unattended

self-modification.

  • No claim that the classic metacognition literature was re-read. It was not (§1).
  • Gap metrics are proxies. Counts of capabilities, tests or sources can all rise while quality falls (R216); the only

defence is outcome measurement on tasks the harness did not design for itself.
