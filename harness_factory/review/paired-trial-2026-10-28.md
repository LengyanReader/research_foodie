# Paired trial · 裸奔 vs harness 配对试验（P45 · D1 阶段 C 的第一份效果测量）

> **中文速览。** 同一任务意图、同一模型、同一会话下的配对试验：**裸奔条件 0.2（1/5），harness 条件 1.0（5/5）**，
> 效果指标=记分集 lit-review 族的 `citation-verifiability`，机器判分。**裸奔条件的缺陷全是真实且可检验的**：一个
> 记错的 id（把 LanguageBind 2310.01852 当成 MemGPT）、一个张冠李戴（Context Engineering 2.0 是概念史论文，不是
> 方法 survey）、一个超出摘要的主张、无溯源、无界定。**诚实边界**：N=1/条件、同模型同会话（污染已声明——测的是
> *过程*不是模型天真的程度）、token=proxy、非受控实验。这是 D1 阶段 C 的**第一份 effect 收据**与机制全链验证。

**Updated:** 2026-10-28 · **Round:** P45 · **Effect metric:** citation-verifiability（lit-review 族，scoreboard §2）· **Judge:** machine（判据预声明，M5.13）

## 1. Design · 设计（判据先于执行）

任务：mini survey——「agent harness 如何驯服长程上下文增长：主要路径与证据」。两条件：
- **A（裸奔）**：单遍、凭记忆引用、不取源、不标访问日期——未装备 harness 的助手回答方式，逐字存档为被测物；
- **B（harness）**：按发射纪律执行——每个主张带已核验来源+访问日期、按源所陈述界定主张、沉默记为沉默（M4.13）。

判据 5 项（预声明于执行前，见项目 `tasks/PLAN.md`）：E1 引用可解析 · E2 主张-来源一致 · E3 无凭空/记错引用 ·
E4 溯源完整 · E5 证据界定。

## 2. Results · 结果

| check | A（裸奔） | B（harness） |
|---|---|---|
| E1 引用可解析 | ✅ 5/5 id 均返回 200（但见 E2/E3——其中 1 个解析到**错误论文**） | ✅ 6/6（含 1 个修正目标） |
| E2 主张-来源一致 | ❌ 2510.26493 内容不符（被当作方法 survey，实为概念史）；2310.01852 完全错配（MemGPT 主张对不上 LanguageBind 摘要）；2304.03442 三因子细节系正文级、摘要未述 | ✅ 逐主张锚定摘要级陈述，正文级细节显式标注「本轮未核验」 |
| E3 无凭空/记错引用 | ❌ MemGPT 记错为 2310.01852（真 id 2310.08560），未加标记地呈现 | ✅ 记错 id 被解析环节当场抓住，修正过程入档 |
| E4 溯源完整 | ❌ 无访问日期、无逐主张指针 | ✅ 全部具备 |
| E5 证据界定 | ❌ 主张无界定；源之沉默未记录 | ✅ 界定+「源之沉默」专节 |
| **score** | **0.2（1/5）** | **1.0（5/5）** |

## 3. What this shows and what it does not · 说明了什么、没说明什么

**说明的**：
1. **机器侧全链可跑**：emit → 双条件执行 → 逐引用机器判分 → 收据入轨迹（tool home 第 3/4 条）——D1 阶段 C 的
   测量机制在真实任务上端到端工作。
2. **效果差距的方向**与库的主张一致：harness 的贡献集中在**可检验性**（E2–E5）——裸奔的失败不是「内容差」，
   而是「无法检验」：没有溯源、没有界定，读者无法把主张还原到源。这正是 M0.1/M0.2 的立库之本。
3. **M5.14 的现场印证**：本试验的两个「被抓错误」（记错 id、张冠李戴）本身就是带诊断的失败记录——已入轨迹，
   是循环的养料。

**没说明的**：
- **不是受控实验**：N=1/条件、同模型同会话、裸奔条件由*同一个已读过这些论文的模型*执行（污染声明）——测的是
  harness 过程对可检验性的贡献，不是「模型没 harness 会多差」的效应量；
- **token 轴是 proxy**（遍数+字数），真实 token 计数待真实运行批次；
- **单一任务族**（lit-review）；其余六族的 effect_metric 未测。

## 5. Second trial (P48) · model-choice 族，带尺度收据

同设计（双条件、同模型、判据预声明），指标=model-choice 族的 `decision-audit-pass-rate`（记录的**结构完整性**，
离线机器可判分）。**收据首次带声明尺度 `scale: [0,1]`**（P45.R1 修复后的首用）。

| check | A（裸奔：选 GPT，凭印象一段话） | B（harness：可审计决策记录） |
|---|---|---|
| E1 模型身份（id+版本，M4.17） | ❌ 裸品牌名 | ✅ id 结构 + 版本槽位，占位显式标 unverified |
| E2 档位纪律（M2.13） | ❌ 无档位 | ✅ 档位作预算行 + 跨档位=设置对比警示 |
| E3 留出检查先声明（M5.13a） | ❌ 事后式「跑一轮看分」 | ✅ 验收标准+拒绝边界先于决策 |
| E4 沉默声明（M4.13） | ❌ 无 | ✅ 「两家相对优劣：源之沉默」+ 本环境不可调用声明 |
| E5 轴归因就绪（M5.13c） | ❌ 无 | ✅ ETCSOVG/模型/环境归因列预留 |
| **score（scale [0,1]）** | **0.0** | **1.0** |

**修复现场验证**：这对收据入轨迹后 `trace-audit` **正确静默**——修复前（尺度盲）两条都会被判低并误触发提案；
修复后 A 的 0.0 单条不足阈值（min_count=2）、B 归一化 1.0 不是低分。**P47 的修复在真实轨迹上生效。**
注意：B 的决策是**条件性暂缓**（本环境无法真实调用两家 API，留出检查未运行）——harness 纪律的产出是「可审计的
决策结构 + 显式的未测声明」，不是假装的结论（M0.4）。
