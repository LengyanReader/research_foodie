## 2. What M4.15 did not catch — and why no new clause

Five of ten findings (R3, I3, I4, I5, G1) are **cross-document drift**: stale counts, a missing group in an
enumeration, a duplicated roadmap, a stale date. M4.15's four defects are *within-document* comprehension
defects; drift is a maintenance defect class the clause does not name.

**Non-addition (M0.5, recorded).** A `cross-doc-consistency` clause would fire on nearly every documentation
task — it cannot discriminate (the `methodology-fit` rule). What actually guards drift here is already in
place: drift-guard tests for generated views, `CountDriftGuardTest` for entry-doc counts, and the two repairs
that generalize — **date the claim** (M0.1) and **don't render the same state twice** (M0.5). No new clause,
no new capability.

**Revisit trigger.** Re-open if a drifted prose claim (not a count) is found to have led an agent to do the
wrong thing — then the gap is a *consequence* problem, not a hygiene one.

## 3. M4.15 operability verdict

The search list is executable and discriminating: it caught 5/10 findings including the highest-value one
(the bare-command precondition — a new user's first command would fail). The uncaptured 5 are a different
defect class, now recorded. **M4.17 (serving-model provenance) remains unexercised by this round** — no model
runs are involved in doc maintenance; its operability check stays open for a round that actually consumes
model output (e.g. the LLM-classifier path).
