# harness-factory · agent-native harness compiler

This repository is a **harness compiler** you consume *directly*: given a task goal, derive the
harness it needs (which invariants, context policy, memory, gates, provenance, tools, governance,
collaboration) and emit it into the target project. The asset is the **knowledge + rules**, not the
executable. You may (a) reason from these files yourself, or (b) call a deterministic CLI if Python is
available. Either way: **select and scaffold — never fabricate task substance** (M0.4).

## ✅ PASTE THIS EXACT INSTRUCTION · 直接粘贴这一句指令（常驻引用）

> **Single source of truth for referencing `harness_factory`.** One line at the start makes the factory a
> **standing reference for the rest of the conversation**; stored in the target project's rules file it
> becomes durable across conversations and subagents. It stops **only when you revoke it**. · 引用本仓库的
> **唯一权威入口**：开头贴一次即成为**常驻引用**（整段对话有效）；写进目标项目的规则文件即**跨对话持久**；
> **只有你明确说停止才停**。把 `./harness_factory` 换成真实路径。

```text
STANDING REFERENCE (until I revoke it) — use ./harness_factory as my harness-factory for this whole conversation.

Reference it like this:
1. Read ./harness_factory/SKILL.md first (its load-index is authoritative).
2. Route by situation: read ./harness_factory/reference/capability-router.md and load ONLY the files the matching row names (index-first, minimal high-signal).
3. If my ask is vague / under-aimed, run ./harness_factory/reference/requirement-refinement.md (R0 restate -> R1 elevate -> R2 classify constraints hard/soft/assumed -> R3 offer MVP/Elevated/Exploratory -> R4 confirm with me -> R5 converge) and WAIT. Do not start work before I confirm.
Standing behaviour: before each substantive answer, check whether a capability applies; when you use one, declare which capability and which file you used. Keep it active until I say "stop using harness_factory".
When deriving a harness: emit only AGENTS.md, tasks/PLAN.md, tasks/PROGRESS.md and .harness/* (incl. capabilities.local.md); keep "Generated by harness-factory" + .harness/manifest.json + provenance; then run `check`.
Bidirectional flow: keep task-specific capability concretisations in the task's own .harness/capabilities.local.md; send only generalisable patterns back as proposals (./harness_factory/updates/, gitignored) — never edit ./harness_factory/data|core|domains|templates directly.
Never fabricate task substance (M0.4); truth/traceability outrank speed (M0.1/M0.2); irreversible acts need my explicit OK.
```

- **Durable form · 持久化。** Paste the same block into the target project's rules file (`AGENTS.md` · `CLAUDE.md` · `.cursor/rules`) so a **new conversation** and **spawned subagents** inherit it. Within one conversation the line alone is enough.
- **Machine-readable pointer · 指针。** A generated harness writes the **resolved** factory path into `.harness/pointer.json` (with `skill_md`, the router, and the refinement/flow docs), and the emitted `AGENTS.md` names that path instead of a placeholder — so a later session never has to be told where the factory is. Check it with `harness doctor --project .`; a `null` `harness_factory` means the factory was not on disk at generation time (ask the user for the path). · 产物里的 `.harness/pointer.json` 记下**解析后的**工厂路径，后续对话无需再报路径；`harness doctor --project .` 可自检是否仍然可达。
- **Revoke · 撤销。** 「停止使用 harness_factory」/ "stop using harness_factory" → back to baseline behaviour.
- **Where to paste.** Claude Code → `CLAUDE.md` or session · Zed/ZCode → Agent Rules / Custom Instructions / `.rules` · Cline · RooCode → Custom Instructions / System Prompt · OpenCode · Aider → `AGENTS.md` or the session.
- **Honest limits (no over-claim) · 诚实边界。** Within one conversation the line persists; after context compaction it survives best as the *rule* in "Standing behaviour". Subagents get fresh context — pass the standing line down or rely on the project rules file. The factory is a policy, not payload: **route first, load files on demand** (or context bloats).

## Cardinal rules — read before emitting anything

1. **Truth and traceability outrank speed (M0.1/M0.2).** Every load-bearing claim traces to a primary
   source (+ access date) or is marked `unverified`. Non-negotiable.
2. **Verify before "done" (M0.3).** "Done" is a verified state with observed evidence, not a feeling.
3. **Machines observe, humans decide substance (M0.4/M0.8).** You may classify, select, scaffold, and
   rank. You may **not** invent the deliverable's content. Irreversible acts (delete / push / publish /
   spend / contact) require explicit human authorization.
4. **Single source of truth; reviewable diffs (M0.5/M0.7).** Emit files, record the plan, don't silently
   mutate. Leave a provenance record.
5. **Refine before executing; propose, don't presume (M0.4/M0.8).** Restate → elevate → classify constraints
   → confirm with the human before working (`reference/requirement-refinement.md`). Anything the loops emit
   is a **proposal** for a human — including capabilities distilled back into this factory
   (`reference/capability-flow.md`).

## Using this repo as a skill · 把本仓库当作 skill 使用

The intended way to use this repo from a **vibe-coding assistant** (Claude Code, Cursor, Codex CLI,
Gemini CLI, OpenCode, …) is to treat it as a **skill**: the assistant reads the rules + catalogs and
does the derivation itself — **no install required (L0)**. Use the CLI (L1) when you need a
deterministic, reproducible scaffold.

### L0 — agent-native (read & reason, no install)

**Two steps — set the config once, then give the task · 两步——先配置一次，再给任务。**
The **configuration** (how to reference and use this tool) never changes, so you paste it **once** — keep it in a
template or the project's rules file. Each **task** is then a short, clean prompt, and you may also send the config
alone first and the task in the **next turn** (or attach files/dirs/links directly). This keeps typing minimal and
lets you reuse the same config for every task. · 配置（如何引用与使用本工具）固定不变，**贴一次**即可——可存为模板
或写进项目规则文件；之后每个任务都是一句干净的短提示。也可以**先只发配置**，**下一轮再发任务**，或直接附上文件/目录/链接。

**Step 1 · 配置（先贴一次，可复用 · paste once, reusable）：**

> 用上文 §**PASTE THIS EXACT INSTRUCTION**（常驻引用）那一版即可 —— 它把「常驻直到撤销」写进了同一条。
> 若只发了配置、还没给任务，助手应**确认收到并等待**，不要提前推导。可复制的完整模板见仓库根
> [`README.md`](../README.md) / [`README.zh-CN.md`](../README.zh-CN.md) 的提示词模板一节。

**Step 2 · 任务（同一轮接着写，或下一轮再发均可 · same turn or next turn）：**

直接写目标，或直接附上文件 / 目录 / 链接。例：

```
为现有 Python 项目补全类型注解与单元测试，保证可验证闭环。
```

助手会据此推导并落盘 harness（`AGENTS.md` + `tasks/*` + `.harness/*`）。

> **可直接复制的模板 · Copy-paste template：** 见仓库根 [`README.md`](../README.md) / [`README.zh-CN.md`](../README.zh-CN.md) 的
> 「Agent prompt templates · 给 agent 的提示词模板」一节（① 配置 + ② 任务句 + 域任务句）。

**What the assistant must do (L0 checklist) · 助手应做的事：**

0. **Standing reference.** If the user pasted §PASTE (or the project rules file carries it), keep it active
   for the **whole conversation** and **declare each capability use** (which capability + which file);
   stop only on explicit revocation. Behavior, not payload — route first, load on demand.
1. **Read the entry** (`harness_factory/SKILL.md`) and follow the **load-index** below; load only what
   the task needs (`reference/derivation-rules.md`, `core/*.md`, `data/*.json`, `domains/<name>/README.md`).
2. **Route & refine.** Match the situation in `reference/capability-router.md`; if the ask is vague or
   under-aimed, run `reference/requirement-refinement.md` (R0–R5) and get explicit confirmation first.
3. **Classify** the goal into the 8-axis feature vector (rules-first; LLM only fills gaps). Match
   against `data/capabilities.json`.
4. **Derive** enabled modules (M0–M8) with reasons + parameters; record `source` and `why` for every
   choice.
5. **Emit** the **output contract** into the target project and fill `PROVENANCE.md` honestly.
6. **Verify** by running the emitted `.harness/check.py` (or `harness check --dir <project>`).
7. **Close the loop** (`reference/capability-flow.md`): keep task-local capability notes in
   `.harness/capabilities.local.md`; propose only generalisable patterns back (`updates/`, human-gated).
8. **Never fabricate task substance** (M0.4); all loop output is a **proposal** for a human.

**Variant prompts · 变体指令词（在「配置」之后，按场景替换任务句）：**

| 场景 | 任务句（接在 Step 1 配置之后） |
|---|---|
| 新项目/新任务搭 harness | 「为『<目标>』推导并落盘所需 harness。」 |
| 只想先看方案、不落盘 | 「先为『<目标>』推导 harness 方案（逐模块给出规则与理由、能力匹配），**只出方案不写文件**。」 |
| 拆解现有项目、学习其能力 | 「用 `profile` 视角扫描 `<项目路径>`，产出 `PROFILE.md` 并作为一个 case 记录（observe-only）；只观察、不改动该项目。」 |
| 按最高标准定目标 | 「按 `domains/excellence/standard-ladder.md`，为『<目标>』定一个 R4 级 apex bar，列出加权 gap 与补齐配置。」 |

### L1 — CLI from path (deterministic, reproducible, no install)

Use this when you want machine-verifiable output (same inputs → same scaffold). Run from the **repo root**:

```bash
# task -> harness plan (explainable: which rule/capability fired and why)
PYTHONPATH=harness_factory/src python -m harness_factory derive --task "<goal>" --json

# task -> harness scaffold on disk (every choice recorded in .harness/manifest.json)
PYTHONPATH=harness_factory/src python -m harness_factory init --task "<goal>" --out <project>
PYTHONPATH=harness_factory/src python -m harness_factory check --dir <project>

# runtime hooks on an emitted harness: gate (structural + runs its check.py), harvest (observe-only)
PYTHONPATH=harness_factory/src python -m harness_factory gate --dir <project>
PYTHONPATH=harness_factory/src python -m harness_factory harvest --dir <project> --root <kb>

# profile / learn a real project (observe-only, project -> factory)
PYTHONPATH=harness_factory/src python -m harness_factory profile --project <project> --goal "<goal>"
PYTHONPATH=harness_factory/src python -m harness_factory learn --project <project> --goal "<goal>"

# agent load-index (same as the table below)
PYTHONPATH=harness_factory/src python -m harness_factory skill          # whole index
PYTHONPATH=harness_factory/src python -m harness_factory skill M4       # one module
```

Notes:
- **Packaging is cancelled** as a distribution channel: there is **no** `uv tool install`/PyPI path.
  Primary consumption = **L0 (agent-native skill)** and **L1 (CLI from path)**.
- If the tool is nonetheless installed on `PATH`, the short form `harness …` works; L0/L1 assume no install.
- **Optional global install.** `install-skill.ps1` copies `SKILL.md` + the knowledge modules + catalogs
  into a skills directory (default `~/.agents/skills/harness-factory`) so a supported assistant can pick
  the skill up globally. Repo-as-skill needs **no** install; this is only for a persistent, global setup.

## How to configure a harness · 如何配置

1. **Classify** the goal into the feature vector (`horizon`, `verifiability`, `stakes`, `grounding`,
   `artifact`, `tool_surface`, `collaboration`, `domain`) — rules first; LLM only fills gaps.
2. **Derive modules** with the rule table; **match capabilities** with `data/capabilities.json`.
3. **Emit** the output contract into the target project (below), and **fill `PROVENANCE.md`** honestly.
4. **Verify**: run `.harness/check.py` (or `harness check --dir <project>`).

## Output contract · 输出契约

```
AGENTS.md · tasks/PLAN.md · tasks/PROGRESS.md
.harness/{manifest.json, gates.md, PROVENANCE.md, check.py, capabilities.local.md}
+ ledger.md (M2) · skills/README.md + skills/<name>/SKILL.md (M6) · decisions.md (M8) · PROFILE.md (if a project was profiled)
```

> `capabilities.local.md` is the **task-local capability ledger** (concretize half of the bidirectional flow);
> see `reference/capability-flow.md`. It stays in the target project.

**Portable skills.** When M6 is enabled, the emitted `.harness/skills/<name>/SKILL.md` follows the
[Agent Skills](https://agentskills.io/specification) open format (`name` + `description` frontmatter,
progressive disclosure), so it loads in any compatible harness — not just the one that generated it.

## Mutual learning · 相互学习

When you configure a project, also **distill it** (`profile`): record its stacks, strong capabilities,
and the harness it got as a **case** (`updates/cases.jsonl`, observe-only). Over time the factory spots
recurring capabilities and proposes registry updates (human-gated) — projects teach the factory, and
capabilities found in one project become reusable options for others. Do not auto-apply; propose.
